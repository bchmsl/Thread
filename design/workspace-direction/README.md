# Thread workspace direction

Status: Proposed visual direction, awaiting review. Existing accepted layouts are available under v0.5 and pilot-notes. Their product rules are the reference during this visual iteration.

| Page | Immediate job | Page structure |
| --- | --- | --- |
| Today | See what needs attention today | Date and checklist lead. Reminders have a time-first tile. Review requests keep their compact GitHub-style row. Active Topics share equal weight below. |
| Topics | Understand the state of each workstream | Four recognizable status lanes. Lane accents encode status. Card edge accents encode Topic identity. |
| Notes | Read or work in a document | Narrow note index and a wide, warm editor surface. Document title, body and save state have distinct roles. |
| Inbox | Decide where a capture belongs | One selected item, clear filing actions and a glimpse of the next item. |

The active navigation item and page title make location visible. Dark surfaces and Topic colors tie the app together. Each page has a layout for its primary job, with only the labels needed to use it.

The standalone preview uses sample data. Navigation, checklist, note switching and Inbox actions are interactive. This is a design comparison. Carry over required behaviors from the detailed page specs, including Topics List and details, broader Inbox capture and scheduling, rich-text editing, and offline/error states. Review the visual direction before extending it to those flows and the remaining pilot pages.
